# Charlotte Desktop Pet MVP 设计

## 1 设计目的

本文定义 Charlotte Desktop Pet 的 Windows MVP 实现方案，统一产品需求、角色与动画约束、后续需求确认结果、技术边界和验收标准。它是详细实施计划与编码工作的上游依据。

项目交付根目录固定为：

`C:\Users\Administrator\Desktop\Charlotte_Desktop_Pet\Charlotte`

运行时产生的用户数据不写入项目目录，而是存放在：

`%LocalAppData%\CharlotteDesktopPet`

## 2 需求来源与优先级

需求冲突时按照以下顺序处理：

1. 用户在讨论中后续明确确认的规则。
2. 《夏洛特桌宠角色与动画设定集 1.0》中的角色和动画约束。
3. `Charlotte_Desktop_Pet_PRD_v1.20.docx`。
4. `Charlotte_Desktop_Pet_PRD_v1.00.docx`。

PRD v1.20 覆盖 v1.00 中冲突的内容；未冲突的细节继续有效。动作参考与角色标准设定冲突时，始终保持角色标准设定；后续用户明确规则与动画文档存在坐标语义差异时，以后续规则为准，同时尽量保持 same body scale、same foot anchor 和 same ground baseline。

## 3 产品目标和非目标

### 3.1 MVP 目标

- 提供稳定、低干扰、可长期运行的 Windows 桌宠体验。
- 支持 Idle、Walk、Rest、Sleep、Click、Drag、Battle 和 Victory 动画状态。
- 使用右键管理面板承载动作预览、每日任务、日程和基础设置。
- 支持最多 7 条每日任务、每日自动重置以及任务完成触发 Victory。
- 支持轻量日程的创建、删除、完成、日期查看和过期显示。
- 支持透明像素穿透、始终置顶、多显示器、Per-Monitor DPI、全屏隐藏、单实例和用户级开机启动。
- 允许先用透明占位帧完成可运行 MVP，再按相同资源契约替换正式动画资产。

### 3.2 非目标

- AI 对话、云同步、账号与多人协作。
- 系统级日程提醒、睡眠唤醒和第三方日历同步。
- 任务分类、复杂重复规则、拖拽排序和复杂优先级。
- 经验值、金币、签到、好感度、商店和重度养成。
- 换装、多角色和角色商城。
- 动作编辑器、骨骼编辑器或逐帧制作工具。
- Live2D 形变、复杂布料模拟和大量实时 GPU 粒子。
- Windows 7/8、32 位 Windows 和 Windows ARM。

## 4 技术路线

### 4.1 平台

- Windows 10 22H2 与 Windows 11。
- Windows x64。
- WPF + .NET 10。
- Release 采用自包含目录发布，用户无需预装 .NET。
- 首个 MVP 不要求安装器；后续可在自包含发布稳定后增加安装器。

### 4.2 选择理由

WPF 能使用 32 位 RGBA 透明 PNG 表现平滑动漫线稿、赛璐璐上色和半透明边缘，并具备成熟的无边框窗口、数据绑定和 Windows 桌面集成能力。透明命中、显示器、全屏检测、单实例和开机启动通过集中式 Win32 互操作层补足。

设定集采用 8 至 14 个关键姿势、低频循环和克制特效，适合 WPF 的 PNG 序列播放器。只有未来改为骨骼形变或复杂实时特效时才需要重新评估渲染引擎。

### 5.1 Charlotte Core

`Charlotte.Core` 是不依赖 WPF 的纯 .NET 业务层，负责：

- 动画状态、动作请求和优先级调度。
- Click 连击窗口和闲置状态转换。
- 每日任务、日程、过期判断和跨天重置。
- 删除撤销规则。
- 横向相对位置模型和边界计算。
- 用户数据、时钟、显示器信息和持久化的接口定义。

### 5.2 Charlotte Windows

`Charlotte.Windows` 是 WPF 可执行程序与组合入口，负责：

- `PetWindow`：透明置顶窗口、帧渲染、Alpha 命中和拖拽。
- `ControlPanelWindow`：动作、每日任务、日程和设置界面。
- `AppCoordinator`：统一协调窗口、动画、显示器、用户数据和应用生命周期。
- PNG 清单解析、图片解码、缓存、特效分层和动画时钟。
- `WindowsInterop`：显示器、DPI、工作区、前台全屏、单实例、开机启动和窗口消息。
- Core 接口的 Windows 和文件系统实现。

UI 只发送用户意图并显示状态，不直接维护另一套业务状态。所有动画和数据状态变化经过 Core，再由可观察状态驱动 WPF 界面。

### 5.3 Charlotte Tests

`Charlotte.Tests` 覆盖 Core 单元测试、资源清单校验、文件恢复测试以及可在无真实显示器环境运行的 Windows 服务计算测试。

## 6 窗口模型

### 6.1 PetWindow

- 无边框、背景透明、不出现在任务栏。
- 默认 `Topmost = true`。
- 只有角色主体的可见像素接收鼠标事件；透明像素把事件传递给下方窗口。MVP 的独立特效层不参与命中，避免花瓣、剑气或气泡形成看不见的阻挡区。
- Alpha 命中阈值由资源清单定义，命中遮罩从已解码帧预计算。
- 窗口尺寸贴近角色和必要特效范围，不使用覆盖整个显示器的透明窗口。

### 6.2 ControlPanelWindow

- 与 PetWindow 分离，保证面板区域不会受角色透明穿透规则影响。
- 右键命中角色可见区域时打开；已打开时再次右键关闭。
- 点击面板外区域或按 Esc 关闭。
- 打开后位置冻结，不持续跟随角色；显示器拓扑变化导致其不可见时允许重新 Clamp。
- 面板打开期间暂停自动 Walk，允许低干扰 Idle。
- 面板按钮、Tab 和输入框操作不触发角色普通 Click。
- 同一次运行期间记住最后选择的 Tab；程序重启后默认进入“每日任务”。
- 底部低视觉权重设置区提供“随 Windows 启动”和“退出程序”。
- 退出程序不二次确认；程序先刷新待保存状态，再关闭。

### 6.3 面板定位

面板以角色 foot anchor 所在显示器的工作区为边界：

1. 优先出现在角色右侧并保留固定视觉间距。
2. 右侧空间不足时切换到左侧。
3. 上下越界时调整 Y，确保完整可见。
4. 面板位置不会跨越到另一显示器以换取空间。

## 7 单实例和启动流程

### 7.1 单实例

程序使用用户会话范围的命名互斥体和本地进程通信通道。重复启动时：

- 不创建第二只桌宠。
- 不重新加载启动位置。
- 不改变已有角色位置。
- 通知现有实例重新执行可见性与置顶策略，然后新进程退出；若当前仍有全屏应用，现有实例保持隐藏。

### 7.2 首次实例启动顺序

1. 获取单实例所有权。
2. 加载并迁移设置与数据，执行跨天检查。
3. 调用 Windows 获取启动瞬间鼠标坐标。
4. 由系统判定鼠标所在显示器；鼠标位于显示器交界时接受系统结果。
5. 读取保存的横向比例并映射到当前显示器可移动横向范围。
6. 对映射结果执行 Clamp；没有历史记录时水平居中。
7. 根据当前显示器 DPI 计算角色显示尺寸。
8. 用 foot anchor 对齐当前显示器的 `WorkArea.Bottom`。
9. 显示角色并启动行为、日期、全屏和显示器监听。

“当前显示器”在启动时仅指鼠标指针所在显示器。程序运行后，角色当前显示器由 foot anchor 所在显示器决定。

## 8 位置和显示器规则

### 8.1 横向位置持久化

程序退出时保存角色在当前显示器可移动横向范围中的比例：

```text
xRatio = (petLeft - workAreaLeft) / (workAreaWidth - petWidth)
```

`xRatio` 限制在 0 到 1。启动时使用目标显示器新的工作区宽度和角色宽度反向映射，随后再次 Clamp。纵向绝对坐标不持久化。

### 8.2 GroundAnchored 与 FreePlaced

- `GroundAnchored`：启动后尚未被用户拖动。任务栏、工作区或 DPI 变化时重新对齐 `WorkArea.Bottom`。
- `FreePlaced`：用户已经拖动。释放点成为本次运行的局部 ground baseline；工作区变化时保留 Y，只有不可见时才 Clamp。

无论角色位于桌面底部还是中部，所有站立与行走动画的 foot anchor 都落在当前有效 baseline 上。因此拖拽结束后角色不处于“离地状态”，而是建立新的局部地面，不违反动作间统一基准线的技术要求。程序重新启动后恢复 `GroundAnchored`，不恢复上一会话的 Y。

### 8.3 拖拽

- 左键在角色可见像素上按下并超过系统拖拽阈值后进入 Drag。
- 保留初始抓取偏移，不把角色中心瞬移到鼠标位置。
- Drag Start 后进入 Drag Hold；拖动时允许跨显示器。
- 角色 foot anchor 进入新显示器后，立即更新 DPI、可见边界和后续面板定位边界。
- 松手后执行位置 Clamp，把释放点设为局部 baseline，播放 Drag Release 并回到 Idle。
- 拖拽是用户直接控制窗口的安全优先操作，可以中止包括不可中断特殊动作在内的当前动画。

### 8.4 DPI 和显示器变化

程序启用 Per-Monitor DPI 感知。角色跨越不同缩放比例显示器时保持近似一致的视觉尺寸，并重新计算：

- WPF 窗口像素尺寸。
- 图片缩放缓存。
- Alpha 命中遮罩。
- 工作区边界和面板锚点。

监听 DPI、显示器拓扑、分辨率、任务栏位置和工作区变化。显示器断开后，把角色 Clamp 到最近的有效工作区。

## 9 始终置顶和全屏例外

角色和面板默认始终置顶。前台其他应用覆盖角色当前显示器的完整显示区域时，将全屏视为唯一例外：

- 隐藏角色和管理面板。
- 停止动画渲染和图片解码，但保留日期检查与数据保存。
- 忽略本程序窗口、桌面 Shell 和短暂过渡窗口。
- 对进入与退出全屏做短时间去抖，避免闪烁。
- 退出全屏后在原位置恢复角色，面板保持关闭。

全屏隐藏期间不逐帧渲染，但动画调度器按单调时间推进逻辑状态。恢复时不补播已经错过的帧：先播放隐藏期间合并得到的一次待处理 Victory，再播放最后保留的面板动作；没有待处理动作时直接进入 Idle。Click 连击状态在进入全屏时清空。

优先使用前台窗口事件；事件钩子不可用时降级为低频轮询。

## 10 动画与资源系统

### 10.1 角色视觉约束

所有正式资产必须保持：

- 日漫 Q 版贵族女剑士定位与 2.5 至 3 头身比例。
- 长奶油金发、深蓝蝴蝶结、蓝紫眼。
- 白色、深蓝、暗红和金色的服装体系。
- 白金高筒靴、深色袜和一致的西洋细剑。
- 相同角色身份、身体比例、服装、镜头角度、foot anchor 和 ground baseline。

只允许改变 Pose、Motion、Expression、Timing、Camera Presentation 和 Effects。不得重新设计发型、发色、眼色、脸型、头身比、服装结构、配色、装饰、鞋袜、剑或角色身份。

### 10.2 外置清单驱动资源

PNG、帧率、循环方式、锚点、调度属性和命中信息由 `config/animations.json` 描述。替换符合契约的正式资产不需要修改代码或重新编译；重启程序后生效。

每个动画条目至少定义：

- 动画名称和资源路径。
- 帧顺序与逐帧时长。
- 预期帧数、循环或一次性。
- 可否中断、返回状态和总时长约束。
- 统一逻辑画布、foot anchor 和 ground baseline。
- 独立 effect layer 与 effect anchor。
- Alpha 命中阈值。
- 是否允许水平镜像。

正式动画默认不水平镜像。只有清单明确允许时才翻转，避免蝴蝶结、剑和服装方向错误。

### 10.3 图片质量

- 正式帧使用透明 32 位 RGBA PNG 和无底色污染的 Alpha 边缘。
- 源分辨率至少为预期显示尺寸的两倍，缩小时采用高质量插值。
- 不使用像素风最近邻缩放。
- 人物层与剑气、花瓣、星光、气泡等特效层尽量分离。
- 武器与特效边界不参与人物主体缩放计算，不能因为特效范围变大而压小角色。
- WPF 使用适合合成的预乘 Alpha 位图，避免透明边缘出现白边、黑边或锯齿。

### 10.4 占位资产

MVP 可使用透明占位或粗加工帧，但必须遵守动作的画布、帧数、顺序、时长、锚点、循环、状态切换和特效数量约束。占位帧只验证播放链路和交互，不代表最终美术质量。

项目保留最小 fallback Idle 资源。某个动作缺失或损坏时禁用该动作并回退 fallback/Idle，不阻止任务和日程继续使用。

## 11 动画状态机

```text
Idle <-> Walk
Idle -> Rest -> Sleep

Idle / Walk / Rest / Sleep
  -> Click / Drag / Battle / Victory / PanelAction
  -> Idle
```

面板打开和全屏隐藏是与动画状态正交的运行标志，不扩张主状态枚举。

### 11.1 动作优先级

从高到低为：

1. 用户拖拽。
2. 正在播放的不可中断特殊动作。
3. 待处理 Victory。
4. 动作面板主动请求。
5. Click 反馈。
6. 自动 Idle、Walk、Rest 和 Sleep。

不可中断 Battle 等动作播放期间：

- 多次 Victory 合并为一次待处理请求。
- 动作面板请求只保留最后一个。
- 普通 Click 直接忽略。
- 当前动作结束后，先播放一次 Victory，再播放最后保留的面板动作，最后回到 Idle。

### 11.2 Click 连击

- 连击窗口为约 1500ms，并作为可配置动画参数保存。
- 第一次播放 Click Soft，8 个关键姿势。
- 第二次允许直接升级切入 Click Annoyed，10 个关键姿势。
- 第三次允许升级切入 Click Warning，12 个关键姿势。
- Warning 播放期间继续点击不重播、不排队。
- 超过连击窗口后，下次点击重新从 Soft 开始。
- MVP 不制作第四级 Sulk 或 Back Turn。

### 11.3 自动行为

- Idle 以“静止 70% + 轻微动作 30%”为节奏目标。
- Walk 为短距离、均匀、低干扰横向移动，到边界前缩短路径。
- 连续 3 分钟无交互进入 Rest。
- 连续 10 分钟无交互进入 Sleep。
- 点击、拖拽、打开面板或完成任务重置闲置计时。
- Rest 可进入 Sleep；多数一次性动作完成后回到 Idle。
- 自动行为时间范围写入配置，测试可注入时钟，不硬编码在 UI。

### 11.4 设定集动作约束

- Idle：8 个关键姿势，轻微呼吸、眨眼、转头、发尾和披风小幅动作。
- Walk：8 帧循环，禁止跑步、蹦跳、滑步和大幅上下起伏。
- Rest：8 帧，立剑小憩，人物高度保持约 Idle 的 95% 至 100%。
- Sleep：人物循环与气泡循环解耦；ZZZ 和 Z 交替，任何时刻只有一个气泡，生命周期约 1.6 至 2.2 秒。
- Drag：Start、4 至 6 帧 Hold 循环和 Release；单次拖拽气泡最多出现一次。
- Battle：14 帧，总时长约 1.1 至 1.5 秒；1 朵小玫瑰、2 至 4 片花瓣、最多 1 次小星光。
- Victory：10 帧，总时长约 0.8 至 1.1 秒；小幅贵族式行礼，只允许 1 至 2 个小星光或微光。

### 11.5 播放器

- 使用单调时钟计算当前帧，不依赖累积 Dispatcher Tick。
- UI 卡顿时跳到正确帧，不高速补播积压帧。
- PNG 在后台解码并冻结为可跨线程使用的 `BitmapSource`。
- 只在帧变化时更新画面，不让 Idle 持续以 60 FPS 空转。
- 缓存遵循内存预算，保留当前动作和即将播放动作，并通过 LRU 回收旧资源。
- 为当前 DPI 生成缩放缓存；跨屏后释放不再使用的缩放版本。

## 12 每日任务

### 12.1 数据字段

每日任务包含稳定 UUID、标题、完成状态、创建时间和固定顺序值。标题去除首尾空格，按 Unicode 字符簇计数，最多 30 个可见字符。

### 12.2 行为

- 最多 7 条，第 7 条存在时新增按钮禁用。
- 空标题不可创建，Enter 确认，Esc 取消。
- 任务保持创建顺序；完成状态变化不重排。
- 未完成转为完成时保留原位置、切换轻量完成样式并产生一次 `TaskCompleted` 事件。
- 完成转为未完成不触发 Victory。
- 同一任务再次从未完成转为完成时可再次触发 Victory。
- 显示“已完成数 / 当前任务总数”，不引入经验值或金币。

## 13 日程

### 13.1 数据字段

日程包含稳定 UUID、标题、本机日期、本机时间、完成状态和创建时间。标题去除首尾空格，按 Unicode 字符簇计数，最多 30 个可见字符。

### 13.2 行为

- 默认显示今天，支持前一天、后一天和返回今天。
- 日程不设硬上限，列表支持滚动。
- 同一天按时间升序，再按创建顺序稳定排列。
- 完成状态变化不重排，不触发 Victory。
- 过期状态不持久化。未完成且日程日期时间早于当前本机日期时间时实时显示为过期。
- 已过期日程不自动完成或删除。
- 日程跨天后保留原状态。
- 日程 Tab 可显示今天未完成数量的轻量数字提示。

## 14 跨天规则

程序在启动、系统唤醒、系统时间或时区变化、每分钟检查以及打开管理面板前比较本机当前日期与 `lastResetDate`。

只要两个日期不同：

1. 把全部每日任务设置为未完成。
2. 刷新完成计数。
3. 把 `lastResetDate` 更新为本机当前日期。
4. 立即持久化。
5. 不弹出提示。

程序信任本机系统日期，不接入网络时间，不防止用户手动改时。日程不参与每日任务重置。

## 15 删除与撤销

- 删除任务或日程后立即从列表移除并保存。
- 保存被删除对象、原索引和类型，显示 5 秒非模态撤销入口。
- 撤销时用原 UUID 和原索引恢复并再次保存。
- 同一时间只保留最近一次删除的撤销入口；下一次删除会使上一项正式结束。
- 恢复已完成任务不触发 Victory，因为它不是一次完成状态转换。

## 16 持久化

```text
%LocalAppData%\CharlotteDesktopPet\
├── data.json
├── settings.json
├── backups\
└── logs\
```

`data.json` 保存每日任务、日程和 `lastResetDate`。`settings.json` 保存横向比例、自启动等用户设置。两者都包含 `schemaVersion`。

所有写入经过单一异步保存队列：

1. 序列化到同目录临时文件。
2. 刷新文件内容到磁盘。
3. 把原文件轮换为最近备份。
4. 原子替换正式文件。

加载失败时依次尝试正式文件和最近备份。两者都损坏时，保留损坏文件，使用空数据安全启动并显示一次低干扰提示。保存失败时保留内存状态，执行有限后台重试。日志默认不记录任务和日程正文。

## 17 开机启动

- MVP 提供“随 Windows 启动”选项，默认关闭。
- 只使用当前用户范围启动项，不申请管理员权限。
- 关闭选项时删除程序自身注册的启动项。
- 注册失败时恢复关闭状态并显示原因。

## 18 错误处理与安全降级

- 单个动画动作缺帧、解码失败或清单无效时禁用该动作并回退 Idle。
- fallback Idle 不可用时显示程序内最小可交互占位视觉，并记录严重错误。
- 配置或数据损坏不阻止桌宠主体启动。
- 文件保存失败不丢弃当前内存状态。
- Windows 事件钩子失败时降级轮询。
- 无法注册自启动时不提升权限。
- 全局未处理异常写入轮换日志，并尽力刷新数据后退出。
- 用户输入正文不写入普通日志。

## 19 性能预算

- 普通 Idle 平均 CPU 目标低于 2%。
- 常规内存目标低于 250 MB。
- 冷启动到角色可见目标不超过 2 秒。
- 已加载情况下管理面板反馈目标低于 100ms。
- 全屏隐藏时停止动画渲染和图片解码。
- 图片缓存、DPI 缩放缓存和 Alpha 遮罩都有明确预算和回收策略。

如果 WPF 透明窗口无法达到预算，先缩小窗口边界、降低无效帧更新、检查图片解码尺寸和缓存，再评估更低层的渲染替代；不在 MVP 预先引入另一套渲染引擎。

## 21 MVP 验收标准

- 角色默认出现在启动时鼠标所在显示器，并贴合 `WorkArea.Bottom`。

- 用户拖放后角色停留在任意可见桌面位置，重启后只恢复横向比例并回到底部基准线。
- 角色透明像素可穿透，可见像素的点击、右键和拖拽稳定。
- 默认始终置顶；当前显示器出现全屏应用时隐藏，退出全屏后恢复。
- 重复启动不会生成第二个实例或改变现有位置。
- 管理面板始终完整位于角色当前显示器工作区。
- Idle、Walk、Rest、Sleep、Click、Drag、Battle 和 Victory 状态稳定切换。
- Click 连击、不可中断动作、Victory 合并和最新面板动作规则准确。
- 每日任务增删、最多 7 条、完成切换、跨天重置和进度显示准确。
- 日程增删、完成切换、日期导航、排序和过期显示准确。
- 任务完成仅在未完成转为完成时触发一次 Victory。
- 删除后 5 秒撤销能恢复对象和原位置。
- 数据重启后保留；损坏文件能从备份恢复或安全降级。
- 动画帧的角色比例、foot anchor、ground baseline、动作节奏和特效数量符合设定集。
- 混合 DPI、多显示器、任务栏变化和全屏切换不会使角色或面板落到不可视区域。

## 22 已知风险与处理

### 22.1 WPF 透明窗口性能

透明分层窗口可能比普通 WPF 窗口更耗资源。通过紧凑窗口边界、按帧更新、后台解码、冻结位图、LRU 缓存和全屏停渲染控制成本，并以真实 Release 构建测量。

### 22.2 高分辨率 PNG 内存

PNG 压缩体积不能代表解码内存。播放器按目标 DPI 解码，并限制同时驻留动作；资源验收报告同时列出文件尺寸和估算解码尺寸。

### 22.3 Alpha 边缘命中

抗锯齿边缘包含低 Alpha 像素，阈值过低会形成看不见的阻挡，过高会让细发丝难以点击。清单提供默认阈值，并使用透明、半透明和主体样例做实机校准。

### 22.4 多显示器拓扑变化

显示器断开、主屏切换和任务栏变化会使历史坐标失效。所有显示器计算使用最新工作区快照，并在窗口消息后集中重新验证和 Clamp。

### 22.5 系统时间变化

本版本信任本机时间，因此手动跨日期可能再次重置每日任务。这是已接受的产品边界，不引入网络时间和防作弊逻辑。

### 22.6 外置资产不一致

画布、角色比例或锚点不一致会产生跳动。启动预检和开发期资源校验命令必须在播放前报告帧数、尺寸、透明通道和锚点差异；程序层不自动拉伸角色来掩盖错误素材。

## 23 实施阶段边界

详细实施计划应按照依赖顺序拆分：

1. 解决方案骨架与 Core 契约。
2. 状态机和领域数据的测试驱动实现。
3. 持久化和跨天逻辑。
4. 动画清单、占位资产和播放器。
5. PetWindow、命中、拖拽和多显示器定位。
6. 管理面板、任务与日程 UI。
7. 单实例、自启动和全屏处理。

编码必须遵循测试先行；每个阶段通过对应测试和构建门后再进入下一阶段。正式动画资产可以在功能 MVP 稳定后逐项替换，但任何替换都必须通过资源校验和角色设定复核。
