# 跨进程透明输入验收

## 自动命中探针

先完成发布，再运行：

```powershell
.\scripts\publish.ps1
.\scripts\test-window-input.ps1
```

探针创建一个独立于桌宠进程的下层测试窗口，不注入鼠标按键，也不移动用户光标。它围绕当前光标依次移动桌宠窗口，使同一个屏幕点先落在透明角落，再落在人物身体区域，并同时读取系统窗口命中结果和 `WS_EX_TRANSPARENT` 状态。

通过条件：

1. 透明角落命中下层测试进程。
2. 透明角落启用 `WS_EX_TRANSPARENT`。
3. 身体区域命中桌宠进程。
4. 身体区域关闭 `WS_EX_TRANSPARENT`。

## 2026-09-13 结果

- Windows 11，DISPLAY1，150% DPI；桌宠物理窗口为 360×450 px。
- 透明命中窗口句柄与下层测试窗口句柄一致。
- 不透明命中窗口句柄与桌宠窗口句柄一致。
- 透明状态为 `true`，不透明状态为 `false`。
- Codex 后台桌面无法读取真实光标，探针记录 `CursorAvailable=false`，并使用与桌宠相同的 `(0,0)` 回退坐标完成窗口级验证。

自动探针证明跨进程窗口命中路由成立，但不注入真实点击。因此快速移入后立即点击、双击、透明边缘点击和按住拖出主体仍保留为已解锁交互桌面上的人工时序验收项。

2026-09-14 在最终 Task 10 发布版上复测：探针可读取真实光标，150% DPI 下主体窗口为 360×450 px；透明点命中下层测试进程且启用 `WS_EX_TRANSPARENT`，身体点命中桌宠进程且关闭该标志，四项条件全部通过。

## 2026-09-14 独立特效窗口

发布后运行 `scripts/test-effect-window.ps1`，以隔离资料目录和 Battle 诊断动作启动真实进程。稳定状态观测到主体窗口 240×300 px、特效窗口 360×420 px；特效窗口扩展样式为 `0x80800A8`，同时包含 `WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE` 和工具窗口标志。由此验证特效范围可独立扩大且不会参与鼠标命中；真实快速点击的人工时序边界仍与上文一致。
